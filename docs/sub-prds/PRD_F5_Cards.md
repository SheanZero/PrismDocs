## 1. 功能概述与目标

理解卡片（Card）是 PrismDocs 对「理解债」痛点（BRD §2.1、§4.2 #5）的回应：AI 辅助开发者普遍"无法充分解释自己的代码库"，而认知科学的对策明确——**只有主动用自己的话重新组织，理解才会留存**。F5 把 Zettelkasten 方法论产品化（BRD §6.3）：阅读靠 Lens，理解留存靠自己写 Card。

Card 是用户手写的原子笔记，可双链到 Document（Base 层）/ Clip / 其他 Card，并可标记为 context-worthy 供 F7 Context Pack 组装——由此 Card 同时是"外部记忆"（BRD 痛点 #2/#3），替代膨胀的 CLAUDE.md，让 AI 不再"忘记"决策。

**对北极星（Closed Loops / week）的间接贡献**：写过卡片的决策，复核更快、resolve 更果断；context-worthy 卡片注入后 AI 更少重犯已被 reject 的方案。直接对应观察指标：人均卡片 ≥3 张/周（AC-5c）。

**本功能的灵魂（不可妥协的产品原则）**：
1. 正文必须用户自己写——**不提供 AI 代写按钮（刻意缺失）**。
2. 引用区与正文在数据层分离，**引用不等于内容**。
3. 原创引导用**柔性提醒**，绝不强制阻止发布。
4. **无文件夹层级**，组织靠双链不靠分类。
5. 「注入上下文」英文行是给 AI 的格式化字段，允许 AI 代译（与"正文不代写"不冲突：正文给人，注入行给 AI）。
6. AI 复述质检为 P0.5：AI 只能在发布后指出"你可能理解偏了"，不能替你写。

## 2. 范围

**In Scope（P0，除标注外）**
- 卡片 CRUD、Markdown 编辑器、标签
- 原创引导：placeholder、引用区折叠、重复度柔性提醒
- 双链（`[[` 联想）、反链面板、失链快照处理
- 场景入口：评论 resolve 提示、选中文字存卡、Cards 栏手动新建
- context-worthy 开关与注入行（英文一句话，AI 可代译）
- 列表、全文搜索、筛选
- AI 复述质检（**P0.5**，可降级）

**Out of Scope（明确不做 / P1）**
- 卡片间隔回顾（spaced repetition）→ P1（主 PRD §1.2）
- 文档间/卡片间图谱视图 → P1
- 卡片正文 AI 代写/润色/续写 → **永不做**（产品原则，非排期问题）
- 卡片被评论（Comment 语义保留给"驱动 AI 改 Document"，同 F6 对 Clip 的约定）
- 多人协作、卡片分享

**与相邻功能的边界与依赖**

| 相邻功能 | 接口方向 | 接口内容 | 边界约定 |
|---|---|---|---|
| F3 段落级评论 | F3 → F5 | resolve 时机触发"写卡提示"，预填评论 quote 与 Document 双链 | F5 不改评论状态；提示可关可禁 |
| F6 剪藏（随 F6 为 P1） | F6 → F5 | Clip 阅读页选中文字"存为卡片"，选区入引用区（MVP 内不激活） | Clip 内容永不自动成为卡片正文 |
| F7 Context Pack | F5 → F7 | context-worthy 卡片被组装器默认预勾选（REQ-7.4）；注入行优先、正文可选（REQ-7.1） | Pack 引用卡片不冻结卡片；删除保护见 §7 |
| MCP（主 PRD §4.2） | F5 → agent | `list_cards(filter)` 检索 context-worthy 卡片（P0.5） | agent 只读，不能创建/删除卡片 |

## 3. 用户故事与关键场景

1. **Resolve 后写卡**：Shean 复核通过"SQLite vs Postgres"评论线程点 resolve，提示"要为这个决策写张卡片吗？"点击进入编辑器，双链与评论 quote 已预填，30 秒写完「SQLite 够用，写入走单队列，迁移点在 storage 层已隔离」。
2. **剪藏选中存卡**：Shean 读一篇 SQLite 并发博客（Clip），选中关键段落 →"存为卡片"→ 选区进入折叠引用区，正文 placeholder 提醒他用自己的话写。
3. **写卡时双链**：正文输入 `[[sql` 唤起联想面板，选中 `docs/architecture.md` 插入双链；保存后该 Document 的反链面板出现这张卡。
4. **勾选 context-worthy**：打开「注入上下文」开关，产品提示补英文注入行，Shean 点"AI 代译"生成 "SQLite is sufficient: single write queue; migration point isolated in storage layer"，微调保存。下次 F7 组装时该卡被默认勾选。
5. **复述质检（P0.5）**：发布后点「AI 质检」，AI 对照引用区与双链对象指出："你写的'单队列'在 Base 文档中是 per-project 队列，跨项目仍可能并发写"——Shean 修正卡片，理解被纠偏。

## 4. 详细功能需求

### REQ-5.1 卡片结构与编辑器（细化主 PRD REQ-5.1）

- REQ-5.1.1 卡片 = 标题（必填，≤120 字符）+ 正文（Markdown）+ 双链 + 标签（0..n）+ 引用区（0..n 条）+ 注入行（可选）。
- REQ-5.1.2 编辑器能力边界：支持基础 Markdown（标题、粗斜体、列表、行内代码、代码块、链接）实时渲染；**不做** slash 命令、表格编辑器、嵌入画板等重编辑能力——卡片应该短，编辑器复杂度是反目标。
- REQ-5.1.3 无文件夹、无手动排序：列表仅按时间/筛选组织；不提供"移动到目录"任何入口（Zettelkasten 原则）。
- REQ-5.1.4 卡片默认归属当前 Project；可改归属或设为 Workspace 级（跨项目通用认知）。
- REQ-5.1.5 软性长度提示：正文 >500 字时编辑器底部提示「这张卡是不是装了不止一个想法？可以拆成几张互链的卡」，不阻止保存。

### REQ-5.2 原创引导（细化主 PRD REQ-5.2）

- REQ-5.2.1 空白正文 placeholder：**「你会怎么向朋友解释这件事？」**（含引用区时追加第二行：「先别看上面的原文，凭记忆写——写完再对照。」）
- REQ-5.2.2 引用区：从 Document/Clip 选中"存为卡片"时，选中内容进入引用区，**默认折叠**，仅显示来源标题 + 首行摘要 + 展开箭头；每条引用带来源双链与选区快照。引用区与正文在数据层分离（quote 表，见 §6），导出/组装时可区分（AC-5b）。
- REQ-5.2.3 柔性提醒触发条件（发布/保存时检测，任一命中即触发，每张卡每次编辑会话最多提醒一次）：
  - a) 正文为空但引用区非空；
  - b) 正文与任一引用条目的字符级相似度 >70%（归一化编辑距离，忽略空白与标点），或正文中存在与引用连续重合 ≥50 字符的片段。
- REQ-5.2.4 柔性提醒文案与交互：非模态横幅——「这张卡的正文和引用原文很像。复制粘贴不会变成你的理解——试试合上原文，用自己的话再讲一遍？」按钮：**[再写写]**（回到编辑器，光标定位正文）/ **[就这样保存]**（正常保存，仅记录埋点）。**绝不阻止保存**。
- REQ-5.2.5 AI 代写刻意缺失：编辑器内不出现任何"AI 生成/润色/续写/总结成卡片"入口；F2/F4 等处的 AI 能力入口不得深链到卡片正文写入。此为验收项（AC-5d-1）。
- REQ-5.2.6 AI 复述质检（**P0.5**）：卡片保存后详情页提供「AI 质检」按钮（编辑态不出现）。输入 = 正文 + 引用区 + 双链对象相关 Block；输出 = 最多 3 条"可能理解偏了的点"，只读批注展示，用户逐条标「已修正 / 不认同」。质检**不产出可一键采纳的替代文本**——只指错，不代写。API key 未配置时按钮置灰。

### REQ-5.3 双链与反链（细化主 PRD REQ-5.3）

- REQ-5.3.1 `[[` 唤起联想面板（v0.2 修订，跨项目）：候选 = **全 Workspace** 的 Document / Card / Clip（当前 Project 优先，跨项目项带项目名徽标；落实原 OQ-5.2）；跨项目链接同时落 F8 的 xref 表（references 型，存储属 F8）。按"标题前缀匹配 > 标题包含 > 最近访问"排序，键盘上下选择、Enter 插入、Esc 取消；输入 3 字符内响应 <100ms（对齐主 PRD §5 性能：2000 卡片规模）。
- REQ-5.3.2 无匹配时提供「新建卡片 "输入文字"」项，创建占位卡并插入链接（快速联想不打断心流）。
- REQ-5.3.3 链接存储为稳定 ID 引用（渲染时解析显示名），对象改名不断链。
- REQ-5.3.4 反链面板：Card / Document / Clip 详情页均显示「被哪些卡片引用」列表（含引用处上下文一行）；这是无文件夹结构下的主要组织浏览方式。
- REQ-5.3.5 失链处理：链接目标被删除时降级为失链态（见 §7），保留显示名快照，悬停提示"源已删除"。

### REQ-5.4 场景入口（细化主 PRD REQ-5.4）

- REQ-5.4.1 评论 resolve 入口：resolve 后就地出现轻量提示条「要为这个决策写张卡片吗？」（8 秒自动消失，不弹模态）；点击进编辑器，预填：标题建议（评论所在 Block 的标题路径末级）、双链到该 Document、评论 quote 进引用区。设置中可关闭。
- REQ-5.4.2 选中文字存卡（v0.2 修订）：Document **Base 视图**的选中浮条含「存为卡片」，选区（Base 原文）进引用区，来源链接指向 Block 锚点。Lens 视图入口随全文 Lens P1（届时双存 Lens 文本 + Base 原文，原 OQ-5.3 就此消解）；Clip 阅读页入口随 F6 P1。
- REQ-5.4.3 Cards 栏「新建卡片」按钮（空白卡）；全局快捷键（默认 ⌘⇧N）。

### REQ-5.5 context-worthy 与注入行（细化主 PRD REQ-5.5）

- REQ-5.5.1 卡片编辑器/详情页提供「注入上下文」开关；开启即 context-worthy，被 F7 组装器默认预勾选（对接 REQ-7.4）。
- REQ-5.5.2 注入行（context line）：**给 AI 的英文一句话格式化字段**，独立于正文存储。开启开关且注入行为空时，就地提示「建议补一句给 AI 的英文版本」：手动输入 / **[AI 代译]**（基于正文生成 ≤200 字符英文，生成后可编辑，用户确认才保存）。此处允许 AI——正文是给人的理解载体，注入行是给 AI 的机读字段。
- REQ-5.5.3 F7 组装时默认仅取注入行（token 紧凑）；注入行为空的 context-worthy 卡片在组装器中标黄提示"无注入行，将使用正文原文（可能含中文）"（对齐 REQ-7.1/7.2）。
- REQ-5.5.4 正文更新后若注入行未变，卡片上显示弱提示"注入行可能过期"，一键重新代译（仍需确认）。

### REQ-5.6 列表、搜索与筛选（细化主 PRD REQ-5.6）

- REQ-5.6.1 Cards 栏列表：卡片流（标题 + 正文首两行 + 标签 + context-worthy 徽标），默认按更新时间倒序。
- REQ-5.6.2 全文搜索：标题 + 正文 + 标签 + 注入行；引用区内容**默认不参与**搜索（引用不等于内容），可勾选"含引用原文"扩大搜索。2000 卡片规模 <300ms（主 PRD §5）。
- REQ-5.6.3 筛选：按标签 / 项目 / context-worthy / 链接对象（"链到某 Document 的所有卡"）组合筛选。

### 新增需求（主 PRD 未覆盖，需回填）

- **REQ-5.NEW-1（需回填主 PRD）** 删除保护：删除被 Context Pack 模板或其他卡片双链引用的卡片时，弹确认框列出引用方（"3 张卡片、1 个 Pack 模板引用了它"），确认后执行 §7 的失链降级；30 天软删除回收站。
- **REQ-5.NEW-2（需回填主 PRD）** 首卡空态引导：Cards 栏首次进入显示引导卡（见 §5 空态）。
- **REQ-5.NEW-3（需回填主 PRD）** 卡片导出：随主 PRD Q3 的 sidecar 备份方案，卡片可整体导出为 Markdown（正文与引用区分节标注），保证数据不锁死。

## 5. 交互与界面规格

**卡片编辑器（核心界面）**

```
┌─────────────────────────────────────────────────┐
│ 标题：SQLite 并发写入的决策                        │
│ 标签：#架构 #存储     [ 注入上下文 ◉ ]            │
├─────────────────────────────────────────────────┤
│ ▸ 引用（2）——来自 docs/architecture.md、Clip     │   ← 默认折叠
├─────────────────────────────────────────────────┤
│ 你会怎么向朋友解释这件事？                         │   ← placeholder
│ 先别看上面的原文，凭记忆写——写完再对照。            │
│ █                                               │
│   （输入 [[ 唤起联想：Document/Card/Clip）        │
├─────────────────────────────────────────────────┤
│ 注入行 (EN)：SQLite is sufficient because ...    │
│                              [AI 代译] [清空]    │
├─────────────────────────────────────────────────┤
│                              [取消]  [保存]      │
└─────────────────────────────────────────────────┘
```

**柔性提醒态**（保存时命中 REQ-5.2.3，编辑器底部非模态横幅）

```
┌─────────────────────────────────────────────────┐
│ ⚠ 这张卡的正文和引用原文很像。复制粘贴不会变成     │
│   你的理解——试试合上原文，用自己的话再讲一遍？     │
│                      [再写写]   [就这样保存]      │
└─────────────────────────────────────────────────┘
```

**卡片详情页**：正文渲染 + 折叠引用区 + 注入行 + 「AI 质检」按钮（P0.5）+ 反链面板（右侧或底部：「被 2 张卡片引用 · 出现在 1 个 Context Pack」）。

**空态（首张卡引导）**：Cards 栏空列表显示——「这里放你用自己的话写下的理解。读文档时选中一段、或 resolve 一条评论，就能开始第一张卡。卡片不进文件夹——用 [[双链]] 把它们连起来。」+ [新建第一张卡片]。

**评论 resolve 提示条**：resolve 后评论线程底部就地出现「✓ 已解决 · 要为这个决策写张卡片吗？[写卡片] [×]」。

**状态一览**：默认态 / 空态 / 柔性提醒态 / 失链态（灰色链接 + 悬停说明）/ 注入行过期弱提示态。

## 6. 数据模型与技术要点（供技术设计参考，非最终 schema）

```
card:  id, project_id(nullable=Workspace 级), title, body_md,
       context_worthy(bool), context_line_en, context_line_stale(bool),
       created_at, updated_at, deleted_at(软删除)
link:  id, src_card_id, target_type(document|card|clip),
       target_id, display_name_snapshot, broken(bool), created_at
quote: id, card_id, source_type(document|clip|comment),
       source_id, block_id(nullable), quote_text_snapshot,
       lens_text_snapshot(nullable), created_at
tag / card_tag: 多对多
```

- 正文（body_md）与引用（quote）分表——这是"引用不等于内容"的数据层落实（AC-5b），也支撑搜索默认排除引用、F7 组装只取正文/注入行。
- 双链解析：保存时从 body_md 提取 `[[id]]` 落 link 表；渲染时按 ID 解析显示名。目标删除 → link.broken=true，display_name_snapshot 兜底渲染；目标恢复（软删恢复/文件重现，经内容哈希识别，同 F1 边界）→ broken 复位。
- quote 永远存快照文本，不实时反查源——源变化不影响已存引用（引用是"当时看到的"）。
- 存储位于 PrismDocs 本地 SQLite（sidecar，主 PRD Q3），不写入用户 repo。

## 7. 边界情况与异常处理

| # | 场景 | 处理 |
|---|---|---|
| 1 | 引用源（Document/Clip）被删除 | 引用降级为快照态：文本保留，标注"源已删除"；双链置 broken（继承主 PRD F5 边界） |
| 2 | 引用的 Block 被 AI 大改/删除 | quote 快照不变；跳转按锚点迁移规则（主 PRD §2.4）落到新位置或文档顶部并提示"原位置已变化" |
| 3 | 卡片互链成环 | 允许（Zettelkasten 常态）；不做环检测告警 |
| 4 | 卡片被 Context Pack（含模板）引用后删除 | REQ-5.NEW-1 确认框；Pack 模板重新生成时跳过并警示（对齐 F7 边界） |
| 5 | context-worthy 卡片中文正文且无注入行 | 允许保存；F7 组装器标黄提示（REQ-5.5.3），F5 侧不阻止 |
| 6 | 超长卡片（正文 >500 字 / >5k token） | 软提示拆卡（REQ-5.1.5）；被 F7 勾选时按其 token 预算规则高亮超支 |
| 7 | 相似度检测误报 | 一键忽略且本编辑会话不重复提醒；仅记埋点，无惩罚 |
| 8 | `[[` 联想 0 结果 | 展示「新建卡片」项（REQ-5.3.2），不出现空面板 |
| 9 | 占位卡（正文为空） | 标"未完成"徽标；不计入人均卡片指标；不可标 context-worthy |
| 10 | AI 质检失败/超时 | 可重试，不影响卡片数据（主 PRD §5 可靠性） |
| 11 | 断网 | 卡片增删改查、双链、引用全部可用；仅 AI 代译与质检不可用（本地优先） |
| 12 | 连续 resolve 多条评论 | 提示条不叠加，仅对最近一条显示；设置可永久关闭 |

## 8. 埋点（opt-in，对齐主 PRD §6）

| 事件 | 属性 | 对应指标 |
|---|---|---|

## 9. 验收标准与测试要点

继承主 PRD：AC-5a、AC-5b、AC-5c。细化：

- **AC-5a-1**：从评论 resolve 提示点击到卡片保存完成，预填齐全时 ≤30 秒、≤5 次交互。
- **AC-5a-2**：从 Clip 选中文字到卡片保存，选区 100% 进入引用区且正文区为空（不预填正文）。
- **AC-5b-1**：数据层校验：任意含引用的卡片，body_md 中不含 quote_text_snapshot 内容（除非用户手动粘贴）；导出文件中正文与引用分节可区分。
- **AC-5b-2**：F7 组装含引用卡片时，默认输出仅含注入行/正文，不含引用原文。
- **AC-5d-1**（新增）：全应用扫查，卡片正文输入路径上不存在任何 AI 生成入口（走查清单验收）。
- **AC-5d-2**（新增）：命中柔性提醒后点「就这样保存」，保存成功且无二次拦截。
- **AC-5e-1**（新增）：2000 卡片压测下 `[[` 联想 <100ms、全文搜索 <300ms。
- **AC-5f-1**（新增）：删除被引用的 Document 后，引用它的卡片：quote 文本完整保留、链接显示失链态、应用无崩溃。
- **AC-5g-1**（新增，P0.5）：AI 质检输出仅含"指出偏差"类批注，不含可整段替换正文的改写文本。

测试要点：锚点迁移场景下 quote 跳转回归（联动 AC-3b 测试集）；相似度阈值用真实内测卡片样本标定；软删除/恢复与 broken 复位的状态机测试。
