## 1. 功能概述与目标

Lens 层生成是 PrismDocs「双层文档」的人类侧一半：对 Base 层（英文技术 Markdown，磁盘文件为权威副本）按 Block 粒度生成简体中文口语化投影。Lens 不是翻译，而是「口语化重述 + 取舍标注」；Lens 是**不可编辑的投影**（产品原则，非技术妥协）——用户对 Lens 的一切不满只能通过 Comment 表达，从根上杜绝双层漂移。

**对北极星指标（闭环数/周）的贡献路径**：Lens 是闭环的第一步。用户能否在 10 分钟内看懂 AI 昨晚写的东西，直接决定他是否会写下第一条 Comment。链路为：Lens 可读（AC-2a）→ 速读区把「需要决策的点」推到用户面前 → 用户在 Lens 段落上评论（F3）→ 回流（F4）→ 复核时靠**变更高亮 + 增量重投影**降低二次阅读成本 → resolve 计入闭环。Lens 的两个质量属性各卡一头：口语可读性决定闭环的发起率，忠实度（失真报告率 <5% 护栏）决定用户敢不敢基于 Lens 拍板。

**目标（MVP）**：内测用户对「只看 Lens 能理解文档 80% 内容」认同率 ≥70%；重投影只触及受影响 Block；失真报告率 <5%。

## 2. 范围

### In Scope

- 简体中文 Lens 的按 Block 生成、缓存与增量重投影
- 速读区（摘要 + 决策清单）
- 阅读三视图（仅 Lens / 对照 / 仅 Base）
- 变更高亮与「标记已读」
- 忠实度保障：一键展开 Base 原文、「需要决策」段强制原文摘录、「报告失真」
- 生成状态管理（流式、失败重试）、token 预估与自动/手动投影策略

### Out of Scope

- 日文/英文等其他目标语言（P1，架构预留语言参数）
- Lens 的任何编辑能力（产品原则，永不做而非后置）
- 评论交互本身（F3）、回流（F4）、Base 层导入与文件监听（F1）
- Lens 内容进入 Context Pack（F7 只打包英文 Base 层内容）

### 与其他功能的边界与依赖

| 相邻功能 | 方向 | 接口/契约 |
|---|---|---|
| F1 导入 | F1 → F2 | F1 产出 Base Document 及 Block 树（§2.4 锚定机制）与变更 diff 事件；F2 消费 diff 决定重投影范围 |
| F3 评论 | F2 → F3 | Lens 段落与 Base Block 一一锚定，F3 在 Lens 上创建的 Comment 经此锚定落到 Block；F2 不管理评论状态 |
| F4 回流 | F4 → F2 | agent 更新 Base 后由 F1 感知变更，F2 自动增量重投影并产生变更高亮，供用户复核（needs-review 的阅读场景由 F2 承载） |
| F7 Context Pack | 无数据依赖 | Lens 内容不进入 Context Pack；共享全局 token 统计（§5 成本可见） |
| Inbox | F2 → Inbox | 「新变更待 review」事项由 F2 的未读变更计数供给 |

## 3. 用户故事与关键场景

**S1 · 首次打开一份英文 spec（P1 用户）**
1. Shean 在文档树点开 Claude Code 刚写的 `docs/architecture.md`；2. 文档 ≤5k token，自动触发投影，Lens 视图逐段流式渲染，速读区最先出现；3. 速读区显示 4 句摘要 + 2 条「❓ 需要你决策」清单；4. 点击清单项跳转到对应段落，该段强制附 Base 原文摘录；5. 全程未读英文正文即形成判断，转入评论（F3）。

**S2 · 复核 AI 修改（闭环后半程）**
1. agent 处理完 Feedback Bundle 更新了 Base；2. F2 收到 diff，仅对受影响 Block 重投影；3. Inbox 出现「1 份文档有变更待 review」；4. Shean 打开文档，3 个变更段落带变更条（修改/新增各有标识），其余段落无高亮；5. 逐段确认后点「标记本文档已读」，变更条清空。

**S3 · 不放心一段中文表述**
1. Shean 读到「⚖️ 选了 SQLite 放弃 Postgres」一段，觉得措辞可疑；2. 一键展开该段 Base 原文对照；3. 发现 Lens 漏了「WAL 模式」限定条件，点「报告失真」并附一句说明；4. 报告入库（埋点 `lens_fidelity_report`），Lens 保持原样——他随后用 Comment 表达修改诉求（Lens 本身不可改）。

**S4 · 大文档的成本把关**
1. 打开一份 18k token 的长文档；2. 项目设置为默认策略，超过 5k 阈值不自动投影，Lens 区显示「预计消耗约 N token，生成 Lens？」；3. Shean 确认后生成；4. 生成期间可切「仅 Base」先浏览结构。

**S5 · key 未配置的新用户**
1. 新用户导入项目后打开文档；2. 未配置 API key，Lens 区显示引导卡片（去设置页配置），Base 层阅读完全不受影响；3. 配置后回到文档，一键触发投影。

## 4. 详细功能需求

以下细化主 PRD REQ-2.1～2.9。

**REQ-2.1 投影粒度与三视图**
- REQ-2.1.1 投影以 §2.4 定义的 Block 为最小单元，Lens 段落与 Base Block 一一锚定（1:1，不合并不拆分），锚定关系存 sidecar 本地库，不写入用户 Markdown。
- REQ-2.1.2 三视图切换：仅 Lens（默认）/ 对照（左右分栏，段落级对齐滚动）/ 仅 Base。切换保持当前阅读位置（按 Block 定位）。
- REQ-2.1.3 视图偏好按文档记忆；无 Lens（未生成/失败）时打开自动落到「仅 Base」并提示。

**REQ-2.2 口语化重述与标记**
- REQ-2.2.1 Lens 为重述而非逐句翻译：允许压缩重复内容、合并句式，但不得增删事实性信息。
- REQ-2.2.2 三类标记内联呈现且可被速读区聚合：⚖️ 取舍决策、⚠️ 风险/待确认、❓ 需要用户决策。判定规则见 §6 prompt 需求。
- REQ-2.2.3 目标读者口径：受过教育但非本领域的读者能懂（主 PRD 原文）；专有名词（API、SQLite、MCP 等）保留英文不硬译。

**REQ-2.3 速读区**
- REQ-2.3.1 文档头部自动生成速读区：3–5 句话摘要 + 「需要决策」事项清单，每条链接跳转到对应 Lens 段落。
- REQ-2.3.2 速读区在任一 Block 重投影后同步刷新（摘要属于「受上下文影响」范畴）。
- REQ-2.3.3 清单为空时显示「本次无需你决策」，给用户明确的「可以关掉」信号（服务「清 Inbox」节奏）。

**REQ-2.4 增量重投影**
- REQ-2.4.1 Base 变更后，仅重投影受影响 Block：diff 直接命中的 Block + 由 diff 判定受上下文影响的相邻 Block（如代码块变更牵连其前后解释段）；未变更 Block 复用缓存。
- REQ-2.4.2 缓存键 = Block 内容哈希 + prompt 版本 + 目标语言 + 模型标识；任一变化即失效。缓存持久化，重启不重算（§5 可靠性）。
- REQ-2.4.3 Block ID 经 F1 迁移存活的 Block，其 Lens 缓存随迁；迁移置信度低（§2.4 降级场景）的 Block 视为新块重投影。

**REQ-2.5 变更高亮与已读**
- REQ-2.5.1 以用户上次「标记已读」为基线，之后发生变化的 Lens 段落显示变更条，区分新增/修改/删除（删除以占位条呈现「此处一段已被删除」，可展开被删 Base 原文快照）。
- REQ-2.5.2 「标记本文档已读」一键清除全部变更条并推进基线；多次连续 Base 变更在同一未读周期内合并显示（不逐次叠加）。
- REQ-2.5.3 未读变更数上报文档树徽标与 Inbox。

**REQ-2.6 忠实度保障**
- REQ-2.6.1 任一 Lens 段落可一键展开对应 Base 原文（就地展开，不跳视图）。
- REQ-2.6.2 含 ❓ 标记的段落**强制**默认附带 Base 原文摘录，不可折叠隐藏（BRD 风险对策，AC-2c 无一例外）。
- REQ-2.6.3 每个 Lens 段落提供「报告失真」：可选原因（漏信息/意思偏了/术语错/其他）+ 可选一句话说明；数据本地留存并计入 `lens_fidelity_report`（opt-in），用于 prompt 迭代与护栏指标。

**REQ-2.7 不可编辑**
- REQ-2.7.1 Lens 全区域只读，无任何进入编辑态的入口；文案上引导「对内容有意见？写评论」（就地拉起 F3 评论入口）。

**REQ-2.8 生成状态**
- REQ-2.8.1 逐段流式渲染，段落完成即可读、可评论；速读区在正文段落完成后生成（依赖全文）。
- REQ-2.8.2 失败段落显示错误摘要 + 单段重试按钮，不阻塞其他段落；整文档级「重试全部失败段」。
- REQ-2.8.3 同一文档同一时刻至多一个投影任务；重复触发合并。

**REQ-2.9 成本控制**
- REQ-2.9.1 手动触发投影前显示预估 token（输入+预估输出）；误差口径对齐 §AC-7b（≤10%）。
- REQ-2.9.2 项目级设置：自动投影 / 手动触发；默认策略为 ≤5k token 自动、超过则提示确认。阈值可在项目设置中调整。
- REQ-2.9.3 投影消耗计入全局 token 统计页（§5 成本可见）。

**新增需求（主 PRD 未覆盖，需回填）**
- REQ-2.NEW-1 投影任务队列可观测：项目级「投影活动」面板，显示排队/进行中/失败任务及日志（AC-2b 的「可通过日志验证」需要产品化承载）。（主 PRD 未覆盖，需回填）
- REQ-2.NEW-2 prompt 版本管理：prompt 变更后旧缓存标记为「旧版本生成」，不强制全量重算（成本），用户可手动「用最新版本重新生成本文档」。（主 PRD 未覆盖，需回填）
- REQ-2.NEW-3 删除段落的 Base 原文快照保留策略：为 REQ-2.5.1 的删除占位条保留最后一版 Base 原文，随「标记已读」清理。（主 PRD 未覆盖，需回填）

## 5. 交互与界面规格

**阅读三视图**：顶栏分段控件 `[仅 Lens] [对照] [仅 Base]`。对照视图左 Lens 右 Base，段落对齐；悬停任一侧高亮对侧对应 Block。

**状态一览**：默认（有缓存，直出）/ 空态（未生成：显示预估 token + 「生成 Lens」按钮；key 未配置：引导卡片）/ 生成中（骨架段落逐个被流式内容替换，顶部细进度条「已完成 m/n 段」）/ 失败（失败段红色占位 + 重试；网络级失败显示全局横幅）。

对照视图 + 变更高亮线框：

```
┌────────────────────────────────────────────────────────────┐
│ architecture.md   [仅 Lens][对照][仅 Base]  ● 3 段变更 [标记已读] │
├────────────────────────────────────────────────────────────┤
│ ◤速读区◢ 这份文档定了存储方案…（4 句摘要）                      │
│ ❓ 需要你决策：1. SQLite vs Postgres → 跳转  2. …            │
├───────────────────────────┬────────────────────────────────┤
│ Lens（中文，只读）          │ Base（英文原文）                 │
│ ▌⚖️ 存储选了 SQLite，理由   │ ## Storage                     │
│ ▌是写入都走单队列…〔改〕     │ We chose SQLite because …      │
│ [展开原文][报告失真][评论]   │                                │
│                           │                                │
│ ❓ 是否接受 1 万用户前不迁移  │ Decision needed: migration     │
│ ┌ Base 原文摘录（强制）──┐  │ threshold …                    │
│ │ "Decision needed: …" │  │                                │
│ └──────────────────────┘  │                                │
└───────────────────────────┴────────────────────────────────┘
```

失真报告弹层：`[漏了信息][意思偏了][术语错误][其他] + 一句话说明（可选）→ 提交`，提交后 toast「已记录，你可以展开原文对照阅读」。

## 6. 数据模型与技术要点（供技术设计参考）

**Lens 缓存结构（sidecar 本地库）**：`lens_segment(block_id, doc_id, lang, content_md, markers[⚖️/⚠️/❓], base_hash, prompt_version, model_id, generated_at, status)`；`lens_digest(doc_id, summary, decision_items[{text, block_id}], base_doc_hash, …)`；`fidelity_report(segment_id, reason, note, created_at)`；已读基线 `read_marker(doc_id, baseline_version, marked_at)`。

**投影任务队列/调度**：按文档串行、跨文档小并发（尊重 API 限流）；任务 = (doc_id, 受影响 block 集, 触发源)；进行中任务遇同文档新变更即取消并以最新版本重新入队（去抖对齐 F1 的 2s 防抖）；失败重试指数退避，429 全局降速。

**Prompt 的产品需求（逐条，供技术设计落地）**：
1. 口语化标准：对「受过教育但非本领域读者」讲人话；短句优先；压缩重复；不引入 Base 没有的事实；专有名词保留英文；数字、版本号、路径逐字保留。
2. ⚖️ 判定：Base 中出现方案对比、被放弃的备选、明示 trade-off 之处必须标 ⚖️ 并用一句话讲清「选了什么、放弃了什么、为什么」。
3. ⚠️ 判定：Base 中的风险、假设、TODO、未验证前提、已知限制标 ⚠️。
4. ❓ 判定：Base 明示需要人拍板（decision needed、open question、请求确认）或存在多个未定方案待选之处标 ❓；宁缺毋滥——❓ 触发强制原文摘录与速读区清单，误报会稀释注意力（对齐 BRD「警报疲劳」约束）。
5. 输出为按 Block 对齐的结构化结果（不得跨块串写），代码块原样透传不重述（其意图由前后解释段覆盖）。
6. 中文/混合语言输入：中文 Block 跳过重述仅参与速读区。

## 7. 边界情况与异常处理

| # | 场景 | 处理 |
|---|---|---|
| 1 | Base 为中文或中英混排 | 逐 Block 语言检测；中文 Block 跳过投影原样呈现，仅参与速读区；英文 Block 正常投影 |
| 2 | 代码块 | 不投影、原样呈现（语法高亮）；前后解释段的 Lens 需覆盖代码意图（prompt 需求 5） |
| 3 | 表格 | 保持表格结构，仅口语化单元格措辞；表头术语保留英文 |
| 4 | 超长文档（>自动阈值） | 不自动投影，显示预估 token 请求确认；超长单 Block（罕见）拆分调用后拼接，仍归属同一 Block 锚点 |
| 5 | 投影进行中 Base 再变更 | 取消进行中任务，以最新版本重新调度（REQ 边界原文）；已完成段落若未受影响则缓存复用 |
| 6 | API 失败/超时 | 单段失败不阻塞其他段；可重试、失败不损坏数据（§5 可靠性）；连续失败暂停队列并横幅提示 |
| 7 | API 限流（429） | 指数退避 + 全局降速；队列面板（REQ-2.NEW-1）显示「限流等待中」 |
| 8 | API key 未配置/额度耗尽 | Lens 区引导卡片；Base 阅读、评论、卡片完全不受影响（本地优先） |
| 9 | 断网 | 已缓存 Lens 可读可评（本地优先）；新投影任务排队待网络恢复 |
| 10 | 文档被外部删除 | 随 F1 归档；Lens 缓存与失真报告保留供追溯 |
| 11 | Block 锚点迁移置信度低 | 视为新 Block 重投影；旧 Lens 段随旧锚点废弃 |
| 12 | 模型输出违规（串块/夹带英文长段/编造） | 结构校验失败即该段标失败可重试，不上屏污染 |

## 8. 埋点（opt-in，对齐主 PRD §6）

| 事件 | 属性 | 对应指标 |
|---|---|---|
| `lens_generated` | doc_id（匿名哈希）、触发源（auto/manual/incremental）、block 总数、重投影 block 数、缓存命中率、输入/输出 token、时长、模型标识、失败段数 | 增量比例验证（AC-2b-1）、成本 |
| `lens_fidelity_report` | segment_id、原因分类、是否 ❓ 段、prompt_version、模型标识 | 护栏：失真率 <5% |
| `lens_view_switched` | 目标视图、停留来源 | 三视图使用分布（Q-F2-2 输入） |
| `lens_base_expanded` | 是否 ❓ 段 | 忠实度信任度旁证 |
| `lens_marked_read` | 未读变更段数、距变更产生时长 | review 节奏 / 闭环前置 |

失真率口径：`lens_fidelity_report 次数 / lens_generated 产出的段落被阅读次数`（内测期近似为报告数/生成段落数）。

## 9. 验收标准与测试要点

细化主 PRD AC-2a～2d：

- AC-2a-1 内测问卷（≥20 人）对「只看 Lens 能理解 80%」认同率 ≥70%。
- AC-2a-2 抽样人工忠实度评估：每轮内测抽 30 个 Lens 段落，双人独立按 5 级量表评（1 严重失真/2 漏关键信息/3 可用有瑕疵/4 忠实/5 忠实且更易懂），≥90% 段落 ≥3 分，0 个 1 分；评分分歧 ≥2 级的段落复议并回灌 prompt 迭代。
- AC-2a-3 三类标记抽检：人工标注 20 份文档金标集，⚖️/⚠️/❓ 的召回 ≥80%，❓ 的精确率 ≥90%（宁缺毋滥）。
- AC-2b-1 修改 Base 中 1 个段落，队列日志（REQ-2.NEW-1）证明仅受影响 Block 被调用，10 秒内呈现。
- AC-2b-2 重启应用后打开已投影文档，0 次 LLM 调用（缓存持久化）。
- AC-2c-1 遍历测试集全部 ❓ 段落，100% 默认附 Base 原文摘录且不可隐藏。
- AC-2d-1 内测期失真报告率 <5%；每份报告可定位到 segment 与 prompt_version。
- 专项：投影中变更竞态（脚本连续写盘 5 次，最终 Lens 与最新 Base 一致、无僵尸任务）；中英混排/纯代码文档/大表格样本回归。

## 10. 依赖与开放问题

**依赖**：F1 的 Block 树与 diff 事件（强依赖，接口需先冻结）；§2.4 锚点迁移算法（技术设计文档）；用户 API key 配置（§1.3）；F3 的段落评论入口挂载点。

**开放问题**

- Q-F2-1（承接主 PRD Q1）模型选型：快速模型打底 + ❓ 段强模型复核的倾向待验证。建议评估方案：用 AC-2a-2 的 30 段抽样集 + AC-2a-3 金标集，对 2–3 档候选模型跑忠实度量表分、❓ 精确率/召回、单文档成本与 P95 延迟四维对比，M0 阶段完成；**结论留开放**。
- Q-F2-2 对照视图是否应在含 ❓ 文档中成为默认视图？主 PRD 定「仅 Lens 默认」，但强制原文摘录已部分覆盖诉求；靠 `lens_view_switched` 数据决策。
- Q-F2-3 速读区刷新成本：每次增量重投影都重生成速读区（依赖全文）可能抵消增量省下的成本，是否允许「速读区延迟刷新/手动刷新」？与主 PRD「增量重投影既是体验也是成本设计」的精神需权衡。
- Q-F2-4 REQ-2.4.1「受上下文影响的相邻块」的判定规则主 PRD 未给出细则（仅「由 diff 决定」），需在技术设计中定义并回填产品口径。
- Q-F2-5 失真报告数据是否随埋点 opt-in 一并关闭，还是本地始终留存仅上报受控？涉及 §5 隐私条款口径，需与隐私需求对齐后定。
