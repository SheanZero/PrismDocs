## 1. 功能概述与目标

Context Pack 是 PrismDocs 的"按需组装外部记忆"：用户勾选 Document（Base 层）、Card（理解卡片）、Clip（剪藏），生成一个紧凑的英文上下文包，写入项目根 `.prismdocs/context/<name>.md`，供 Claude Code / Cursor 通过文件引用或 MCP 工具 `get_context_pack` 消费。

它直接回应 BRD 三个痛点：

- **痛点 #2（AI 忘记决策）**：context-worthy 卡片是原子化的外部记忆，Pack 让它们在新会话开始时"按需注入"，/compact 后不再蒸发。
- **痛点 #3（CLAUDE.md 膨胀失效）**：Pack 替代"什么都塞进一个巨型文件"的模式——CLAUDE.md 保持极简协议说明，具体上下文按任务临时组包。
- **痛点 #9（token 焦虑，BRD 设计约束）**：组装全程实时显示总 token 与各项占比（误差 ≤10%），用户"看着数字做取舍"。

**对北极星的贡献路径**：北极星是"评论→AI 修改→复核通过"闭环数/周。Pack 不直接产生闭环，但决定闭环的起点质量——新一轮 agent 会话带着正确的决策记忆开工，减少"AI 忘记约定→用户重复批注"的无效循环；同时 `clip_used_in_pack` 支撑 BRD"剪藏→被引用进上下文 ≥25%"的指标。

**必守产品原则**：① Pack 内容纯英文倾向（给 AI 的层保持紧凑英文、省 token）；② token 实时可见且误差 ≤10%；③ 组装的是 **Base 层**内容，Lens 是给人的投影，永不进 Pack；④ 本地优先，组装与生成不经过任何服务器（AI 压缩/英译除外，走用户自备 API key）。

## 2. 范围

**In Scope（P0）**：组装器面板（树形勾选 + 实时 token 条）；**Workspace 作用域勾选**（含其他项目文档，v0.3 新增）；Pack 生成写入 `.prismdocs/context/`；context-worthy 卡片默认预勾选；token 预算设置与超支高亮；模板保存/复用/失效提示；MCP `get_context_pack`；中文卡片正文的"机器英译 / 原文保留"选项。

**P0.5（尽力，可降级）**：导出 OKF Bundle（对应主 PRD REQ-7.6，v0.2 新增，见本文 REQ-7.6.x）。

**随 F6 转 P1（v0.3）**：Clip 勾选与 Clip 的"AI 压缩版"。

**Out of Scope**：Pack 内容的语义去重与自动排序优化；按任务描述自动推荐勾选项（P1）；Pack 云同步/分享；把 Lens 内容打包（原则性排除）；agent 侧写回 Pack（MCP 对 Pack 只读，与主 PRD §4.2 安全约定一致）；MCP `export_okf_bundle` 工具为 **P1**（主 PRD §4.2 v0.2 新增，MVP 内仅提供 UI 导出入口，agent 侧导出不做）。

## 3. 用户故事与关键场景

**S1 · 新会话前组包（主场景）**：Shean 要开新一轮 Claude Code 会话做 storage 层重构。打开组装器，3 张 context-worthy 卡片已预勾选（含「SQLite 够用，迁移点在 storage 层已隔离」），再勾 `docs/architecture.md` 和 1 个 SQLite 并发的 Clip。token 条显示 6.2k。点生成，得到 `.prismdocs/context/storage-refactor.md`，复制引导语到剪贴板，对 Claude Code 说一句话开工。

**S2 · 保存模板复用**：Shean 发现每次会话都要带同一批架构决策，把当前勾选存为模板「架构决策包」。此后从模板一键重组，30 秒出包。

**S3 · 文档更新后的重生成提示**：agent 修改了 `architecture.md`。Shean 再次打开「架构决策包」模板时，该项标注"内容已变化（2 小时前）"，重新生成即拾取最新 Base 内容。

**S4 · 超预算裁剪**：Shean 设了 8k token 预算，勾选一个 12k 的长 Clip 后总量超支。token 条变红，超支项高亮并提示"生成 AI 压缩版（约 1.5k）或取消勾选"。他选压缩版，回到预算内。

**S5 · MCP 直拉**：Shean 在 CLAUDE.md 里写了"任务开始前先 `get_context_pack("arch-decisions")`"。agent 每次开工自动拉取最新 Pack，无需人手动引用文件。

## 4. 详细功能需求

### REQ-7.1 组装器（细化）

- **REQ-7.1.1**（v0.3 修订，Workspace 作用域）树形勾选器分区：Documents——默认展示当前项目文档树（镜像磁盘目录结构），其上提供「其他项目」分组（按项目折叠，契约文档带徽标置顶；典型用法：client 的 Pack 带上 server 的契约文档）；Cards（全 Workspace，context-worthy 置顶）；Clips（随 F6 为 P1，P1 前该分区隐藏）。支持父节点全选/半选、搜索过滤。
- **REQ-7.1.2** 每个可勾选项右侧实时显示该项 token 数；卡片区分「注入行 only」（默认）与「注入行 + 正文」两档，切换即时反映到 token 条。
- **REQ-7.1.3** 默认勾选逻辑：本项目全部 context-worthy 卡片预勾选（= 主 PRD REQ-7.4）；Document 与 Clip 默认不勾选；从模板打开时按模板记录恢复勾选。
- **REQ-7.1.4** 实时 token 条：底部常驻，显示 总数 / 预算、按来源类型（Docs/Cards/Clips）分色堆叠占比；每次勾选变化 ≤200ms 内更新（长文档 token 数预计算缓存）。
- **REQ-7.1.5**（随 F6 为 P1，v0.3 调整）Clip 可选"AI 压缩版"：调用 LLM 生成英文要点摘要（保留代码块原文），压缩版与原文并存，勾选器中显示两者 token 对比；压缩失败回退原文。

### REQ-7.2 输出格式（细化）

- **REQ-7.2.1** 生成文件写入 `.prismdocs/context/<name>.md`；`<name>` 由用户命名，slug 化（小写、连字符），非法字符自动替换。
- **REQ-7.2.2** 结构：头部元数据（YAML）+ 使用说明 → Key Decisions（Cards）→ Documents → Reference Clips。卡片排最前——外部记忆优先级最高且最省 token。
- **REQ-7.2.3** 语言策略：Pack 骨架与说明文字一律英文。卡片注入行本就要求英文（F5 REQ-5.5）；勾选了中文卡片正文或中文 Clip 时，逐项提供选项：**Translate to English（默认，调用 LLM 机器英译，标注 machine-translated）/ Keep original**。未配置 API key 时英译选项置灰，回退原文保留。
- **REQ-7.2.4** 完整格式示例（生成物即如下形态）：

### REQ-7.3 模板（细化）

- **REQ-7.3.1** 模板保存的是**引用与配置**（勾选项 ID 集合、各项档位、语言选项、预算），不保存内容快照；每次"从模板生成"都取各来源的最新内容。
- **REQ-7.3.2** 失效提示：打开模板或从模板生成前，逐项校验——内容自上次生成后变化的项标注"内容已变化"；来源已删除的项标注"源已删除"并默认剔除（见 §7）。
- **REQ-7.3.3** 模板列表：名称、项数、上次生成时间、上次生成 token 数；支持重命名/删除/复制。

### REQ-7.4 默认勾选（细化）

- **REQ-7.4.1** 见 REQ-7.1.3。补充：用户手动取消某张 context-worthy 卡片后，本次会话内不再自动回勾；不持久化取消状态（避免与 F5 的 context-worthy 标记语义冲突——想永久移出请去卡片上关掉开关，组装器就地提供该开关入口）。

### REQ-7.5 MCP 打通（细化）

- **REQ-7.5.1** `get_context_pack(name)` 返回 `.prismdocs/context/<name>.md` 的当前文件内容（含 YAML 头）；不存在时返回错误与现有 Pack 名列表。
- **REQ-7.5.2** MCP 对 Pack **只读**：不提供 agent 侧生成/修改 Pack 的工具（与主 PRD §4.2 "写操作限于评论回执"一致）。
- **REQ-7.5.3** 拉取即时性：返回的是最近一次用户生成的静态文件，不隐式重组装。**主 PRD 未明确 agent 拉取时源文档已变化是否提示**，列入开放问题 Q3。
- **REQ-7.NEW-1**（主 PRD 未覆盖，需回填）**token 预算设置**：主 PRD 边界情况提及"用户设定的 token 预算"但无对应 REQ。定义：项目级默认预算（默认 8,000 token，可改/可关）+ 单次组装可临时覆盖；超支不阻止生成，仅警示（用户自主取舍，见 S4）。
- **REQ-7.NEW-2**（主 PRD 未覆盖，需回填）**生成成功态与喂 agent 引导**：生成后展示成功面板——文件路径、最终 token 数，并一键复制引导语（英文，如 `Read .prismdocs/context/storage-refactor.md before starting.`）；已装 MCP 的用户同时展示 `get_context_pack("storage-refactor")` 用法。对齐 F4 REQ-4.2 的剪贴板模式。
- **REQ-7.NEW-3**（主 PRD 未覆盖，需回填）**同名 Pack 处理**：生成到已存在的 `<name>` 时提示"覆盖 / 另存新名"；覆盖保留上一版为 `.prismdocs/context/.history/<name>.<timestamp>.md`（本地保留最近 3 版）。

### REQ-7.6 导出 OKF Bundle（细化，v0.2 新增，P0.5）

细化主 PRD REQ-7.6，遵循主 PRD §2.5 OKF 兼容约定。这是组装器的**第二种输出形态**：Context Pack 是"喂 agent 的单文件快照"，OKF Bundle 是"可被任何 OKF 消费方读取的多文件知识包"；两者共用同一套勾选。

- **REQ-7.6.1 导出入口**：组装器底部提供"导出为 OKF Bundle"按钮，与「生成 Pack」并列；沿用当前勾选集（Documents/Cards/Clips），不受 token 预算约束（导出物给 OKF 消费方，非注入上下文，token 条对此形态不计红线）。
- **REQ-7.6.2 目录结构**：用户选择导出目录后，生成 `<导出目录>/index.md`（自动生成的 bundle 导航：按类型分组列出全部导出对象及一行摘要，OKF 保留文件名语义）+ 按类型分子目录：`docs/`（Document）、`cards/`（Card）、`clips/`（Clip）。文件名 slug 化，Document 保留其在项目内的相对路径层级于 `docs/` 下。
- **REQ-7.6.3 frontmatter 物化规则**：sidecar 元数据在导出时物化为标准六字段（`type`/`title`/`description`/`resource`/`tags`/`timestamp`，主 PRD §2.5；源文件保持不污染）。分对象：
  - **Document**：`type` 取其受控词表值（`Spec` / `Plan` / `Architecture` / `Decision` / `Runbook` / `Doc`（缺省））；已有 frontmatter 的字段往返保留。
  - **Card** → `type: Card`：英文注入行写入 `description`（无注入行时策略见 E13）或正文首行；卡片的"引用区"保持折叠语义——引用不展开为全文，而是输出为**带来源链接的引文块**（blockquote + 指向来源的 Markdown 链接）。
  - **Clip** → `type: Clip`：来源 URL 写入 `resource`，抓取时间写入 `timestamp`；正文为净化后 Markdown。
- **REQ-7.6.4 跨链接重写**：对象间的内部双链/相对链接重写为 bundle 内相对 Markdown 链接（如 `../docs/architecture.md`），使目录可被 OKF 工具解析为图；指向**未导出**对象的链接降级为纯文本（保留链接文字，去掉链接语法），并在导出报告中逐条列出。
- **REQ-7.6.5 合规性与导出报告**：导出物满足 OKF v0.1 conformance——每文件 `type` 必填、UTF-8 编码、纯 Markdown + YAML frontmatter（无私有二进制/运行时依赖）；导出完成后展示导出报告：文件数（按类型）、告警列表（降级链接、未登记 type、无注入行卡片等）。

导出后目录树与单个 Card 文件示例：

```
okf-export/
  index.md                      # bundle 导航（自动生成）
  docs/
    architecture.md             # type: Architecture
  cards/
    sqlite-is-sufficient.md     # type: Card
  clips/
    sqlite-write-concurrency.md # type: Clip
```

```markdown
---
type: Card
title: SQLite 够用，迁移点在 storage 层已隔离
description: SQLite is sufficient for our scale; migration point is isolated in the storage layer.
tags: [storage, decision]
timestamp: 2026-07-26T14:30:00+08:00
---
We decided this after load testing at 10k users...

> 引用：[SQLite Write Concurrency in Practice](../clips/sqlite-write-concurrency.md)
```

## 5. 交互与界面规格

组装器为全屏模态（从项目页「组装上下文」按钮或模板列表进入），左树右预览两栏 + 底部 token 条：

│ 名称: [storage-refactor  ]  模板: [从模板…▾] [存为模板]      │
├───────────────────────────┬────────────────────────────────┤
│ ▾ Documents               │  预览（生成物结构）              │
│   ▾ docs/                 │  ─────────────────────────      │
│     ☑ architecture.md 3.4k│  ## Key Decisions (Cards)       │
│     ☐ api-spec.md    2.1k │   • SQLite is sufficient…  41t  │
│ ▾ Cards (context-worthy 置顶)│   • Auth tokens in keychain…  │
│   ☑ SQLite 够用… [注入行▾] 41t│ ## Documents                  │
│   ☑ 密钥进钥匙串… 15t      │   architecture.md (full) 3.4k  │
│ ▾ Clips                   │  ## Reference Clips             │
│   ☑ SQLite Concurrency    │   SQLite Concurrency (AI压缩)   │

└────────────────────────────────────────────────────────────┘

**状态定义**：

- **默认态**：context-worthy 卡片预勾选，token 条绿色。
- **空态**：项目无任何可选项时，引导文案指向 F5（"把关键决策写成卡片并开启注入"）与 F6。
- **超预算警示态**：token 条变红显示超出量；超支后新勾选的项目行尾高亮，附「AI 压缩」「仅注入行」「取消勾选」快捷动作；生成按钮仍可用，文案变为「仍要生成（超预算）」。
- **生成成功态**：见 REQ-7.NEW-2，含"下一步喂给 agent"的两条路径引导。
- **模板列表**：项目页二级入口，行内显示失效徽标（"2 项已变化 / 1 项源已删"）。

**导出 OKF Bundle 流程（v0.2 新增，对应 REQ-7.6）**：点击「导出为 OKF Bundle」→ 系统目录选择器选定导出目录（记忆上次选择；目录非空且已含 `index.md` 时按 E14 覆盖确认）→ 执行导出（进度轻提示）→ 弹出**导出报告弹窗**：文件数按类型统计（docs/cards/clips）、告警列表（降级链接、未登记 type、无注入行卡片），提供「打开导出目录」与「复制报告」动作。

## 6. 数据模型与技术要点（供技术设计参考，非约束）

**表结构建议**（SQLite，本地库，与主 PRD §5 一致）：

- `pack`：id、project_id、name(slug)、budget、language_option、total_tokens、file_path、generated_at、template_id(nullable)
- `pack_item`：pack_id、source_type(document/card/clip)、source_id、mode(full / injection_line / injection_plus_body / ai_compressed)、tokens、source_hash（生成时内容哈希）、order
- `pack_template`：id、project_id、name、config_json（勾选项引用 + 档位 + 预算 + 语言选项）、last_generated_at

**token 计数策略**：本地内置 tokenizer，不为计数联网。建议以 `tiktoken`（o200k_base）或 Anthropic 官方 tokenizer 的本地实现打底；因用户可能对接多家模型，UI 明示"按 ~Claude 口径估算"。AC-7b/AC-6c 的 ≤10% 误差以用户配置端点的实际计数为基准验证。与 F6 的 Clip token 估算复用同一组件，避免两处数字打架。

**快照 vs 引用**：模板存引用（REQ-7.3.1）；生成的 Pack 文件是**内容快照**（agent 读到的必须是确定性文本，不能生成后随源漂移）；`pack_item.source_hash` 用于模板失效检测与埋点归因。AI 压缩版作为 Clip 的派生字段缓存，源 Clip 不变则不重复调用 LLM。

## 7. 边界情况与异常处理

| # | 场景 | 处理 |
|---|---|---|
| E1 | 勾选内容超 token 预算 | 不阻止生成；token 条红色、超支项高亮，提供压缩/降档/取消勾选快捷动作（主 PRD 边界情况细化） |
| E2 | 模板/勾选引用的 Document 已删除（archived） | 生成时跳过该项，Pack 头部与成功面板列出警示"1 item skipped: source deleted"（主 PRD 边界情况细化） |
| E3 | context-worthy 卡片无英文注入行 | 不静默丢弃：提示补写或一键 AI 代译注入行（F5 REQ-5.5 允许代译该字段）；用户跳过则回退用正文（附英译选项）并在项上标注 |
| E4 | Clip 超长（>50k token）且未压缩 | 勾选时即警示；无 API key 无法压缩时建议取消勾选或回 F6 做选区重剪 |
| E5 | 预算冲突：模板保存的预算 ≠ 当前项目默认预算 | 以模板保存值为准并在 token 条旁标注"模板预算" |
| E6 | 同名 Pack 覆盖 | 按 REQ-7.NEW-3：确认 + 本地保留历史版本 |
| E7 | 生成过程中源文件被 agent 修改 | 以点击「生成」瞬间的内容为快照；完成后检测到源已变化则在成功面板提示"生成期间源已更新，可重新生成" |
| E8 | `.prismdocs/context/` 不存在或不可写 | 自动创建；不可写（权限/只读卷）时报错并给出路径，Pack 内容暂存本地库可导出 |
| E9 | 英译/压缩 LLM 调用失败 | 单项回退原文并标注 untranslated/uncompressed，不阻塞整包生成（对齐主 PRD 可靠性要求） |
| E10 | 卡片正文为空（仅注入行） | 正常，仅输出注入行；不视为异常 |
| E11 | Pack 名与 `.prismdocs/feedback/` 等协议文件冲突 | Pack 只写入 `context/` 子目录，天然隔离；保留字（`.history` 等）禁用为 Pack 名 |
| E12 | 导出对象的 type 未在受控词表登记（主 PRD REQ-1.8 的"未登记"态） | 不阻塞导出：Document 回退 `type: Doc`（缺省值），原始 type 值保留为扩展字段 `x-original-type`，并在导出报告告警中列出 |
| E13 | 卡片无英文注入行时 `description` 取值 | 优先取正文首行（截断至 ~200 字符）；正文亦为空则省略 `description`（OKF 仅 `type` 必填），导出报告告警提示补写注入行 |
| E14 | 重复导出到同一目录 | 检测目标目录已含 `index.md`（视为既有 bundle）时弹覆盖确认："覆盖（同名文件替换、`index.md` 重新生成）/ 另选目录"；不静默覆盖，不清除目录内非本次导出的文件 |

## 9. 验收标准与测试要点

- **AC-7a-1**（细化主 PRD AC-7a）：生成的 Pack 通过文件引用被 Claude Code 读取后，agent 能在后续回答中正确复述其中至少 1 条 Key Decision（真实项目验证）。
- **AC-7a-2**：同一 Pack 经 `get_context_pack` 拉取，内容与磁盘文件逐字节一致。
- **AC-7b-1**：对 ≥10 个混合 Pack（含中英内容、代码块），token 显示与用户配置端点实际计数误差 ≤10%；勾选变化后 token 条 ≤200ms 更新。
- **AC-7c-1**：从打开组装器到生成完成 ≤60 秒（不含 AI 压缩/英译）；从模板重新生成 ≤30 秒。
- **AC-7d-1**：context-worthy 卡片 100% 预勾选；无注入行的卡片按 E3 处理，0 静默丢弃。
- **AC-7e-1**：模板中源已变化/已删除的项，打开时 100% 显示失效标注；已删项不进入生成物。
- **AC-7d**（v0.2 新增，对应主 PRD REQ-7.6；编号沿用主 PRD AC 序列，区别于本文细化条目 AC-7d-1）：导出的 bundle 通过 OKF 参考可视化工具（GoogleCloudPlatform/knowledge-catalog 的 visualizer）可正常解析出图。
- **测试要点**：断网生成纯引用 Pack（无英译/压缩）全流程可用（本地优先）；`.gitignore` 建议覆盖 `context/`（复用 F1/F4 的 `.prismdocs/` 初始化提示）；与 F4 Feedback Bundle 并存时 MCP 工具互不串扰。
