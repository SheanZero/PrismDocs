<objective>
关闭本轮 WR-03、上轮 WR-14、上轮 WR-12 与上轮 IN-04：

- **本轮 WR-03**（两个缺口相互放大）：
  1. `rejections_do_not_disclose_which_layer_denied`（第 425 行）跑的是三个**隔离 sentinel router**，从不跑 `serve_loopback`。而真正打到实发路由的 A 组测试对 bearer 情形只断言 `is_client_error()`（第 192-204 行）——回归到 401 / 400 / 404 照样绿，而那正是 T-01-29 禁止的状态码分化。
  2. `build_router` 刻意把 SDK 侧配成同一份 allowlist 做防御纵深，但 **SDK 的拒绝不是无差别的**：rmcp 2.2 的 `tower.rs` 会返回 `forbidden_response("Forbidden: Host header is not allowed")`（403 **带正文且点名层次**）与 `bad_request_response("Bad Request: Invalid Host header")`（**400** 带正文）。两层可达是因为解析宽严不同：应用层 `host_of` 接受第一个 `:` 之前的任何东西，SDK 用更严的 `Authority::try_from`——`Host: 127.0.0.1:notanumber` 过得了第一层、从 SDK 拿到一个带正文的 400。可达性需要合法 bearer，所以不是未鉴权 oracle（因此是 WARNING 不是 BLOCKER），但那条被写进文档的性质（「三层一律返回 403 且空正文」）端到端**是假的**，且没有任何测试会注意到它在鉴权前也变假。
- **上轮 WR-14**：`accepts_fully_valid_request` 是 A 组的阴性对照，断言 `!status.is_client_error()`——一个 500、502 或任何服务端失败都满足它。这条测试知道成功长什么样，没有理由用宽松形态。
- **上轮 WR-12**：`PrismHandler` 的工具描述符声明 `"required": ["projectId"]` 与 `"type": "string"`，`call_tool` 随即把两者都丢掉（`.unwrap_or_default()`）。没有 `arguments`、`projectId` 缺失、`projectId: 42` / `null` 一律被静默强转成空串。今天靠 `Engine::list_feedback` 拒绝空串兜住，但那是**被注入实现**的校验在替 handler 的校验兜底，而 handler 正是 Phase 6 要扩展的地方。返回的错误类别也是错的：一个格式错误的请求被报成 `internal_error` 而不是 invalid-params。
- **上轮 IN-04**：`require_local_host` 要求字面 `Host` 头，缺席即拒。HTTP/2 下 authority 走 `:authority` 伪头且 hyper 不合成 `Host`——rmcp 正是这么处理的（`tower.rs` 有一条注释说明 `axum::Router::nest` 可能丢掉合成头）。明文 HTTP/2 需要 prior-knowledge 协商，所以今天没有客户端会撞上，但任何未来的 h2 客户端会拿到一个无从诊断的 403。

Purpose: 本轮评审点破的主线是「correct guards protected by non-discriminating tests」，WR-03 是它最完整的实例——**代码是对的，但断言会在它本该抓住的那个回归上保持绿色**，而且真实路由从来没被那条契约测试碰过。

Output: 一组打在实发路由上的契约断言、一个执行自己 schema 的 handler，以及一条对 `host_of` 与 SDK 口径关系的明确定案。
</objective>
