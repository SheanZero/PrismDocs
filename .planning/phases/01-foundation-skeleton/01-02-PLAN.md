  <action>
    断言逻辑的**唯一实现**放在 `scripts/check-deps.sh`（`#!/usr/bin/env bash` + `set -euo pipefail`），
    因为 `just` 在本机未安装且 RESEARCH § Environment Availability 已把它列为「可用 shell 脚本替代、不阻塞」。
    脚本接受一个子命令参数：`dup` | `tauri-free` | `no-cycle` | `single-egress` | `all`，无参数时等同 `all`。
    每条断言失败时打印违规的 crate 名并 `exit 1`，成功时打印一行以 `OK` 开头的消息并 `exit 0`。

    脚本内定义两个集合变量：
    `ENGINE_CRATES="prism-types prism-store prism-fs prism-parse prism-anchor prism-llm prism-mcp prism-engine"`，
    `PURE_CRATES="prism-types prism-store prism-fs prism-parse prism-anchor prism-engine"`
    （后者是 single-egress 的受检集合——排除 prism-llm 与 prism-cli 这两个被允许触网/触密钥的包）。

    四条断言：
    - `dup`：跑 `cargo tree --workspace --duplicates --edges normal`，若输出中出现以
      `rusqlite v` / `reqwest v` / `libsqlite3-sys v` 开头的行即判失败（`--duplicates` 只列多版本共存的包，
      命中即意味着同一进程会链接两份 SQLite/HTTP 栈）。
    - `tauri-free`：对 ENGINE_CRATES 逐个跑 `cargo tree -p "$c" --edges normal,build --prefix none`，
      命中以 `tauri ` 开头的行即失败。用 `normal,build` 而不是只 `normal`——build script 依赖同样会把
      tauri 拖进 engine 的构建图。
    - `no-cycle`：跑 `cargo tree -p prism-mcp --edges normal --prefix none`，跳过树根首行后命中以
      `prism-engine ` 开头的行即失败。**必须是 `--edges normal`**：cargo 允许「A→B 普通依赖 + B→A dev
      依赖」这种环存在且普通编译不报错，dev 边是 D-09 唯一的逃逸口。
    - `single-egress`：对 PURE_CRATES 逐个跑 `cargo tree -p "$c" --edges normal --prefix none`，
      命中以 `reqwest ` / `keyring-core ` / `apple-native-keyring-store ` 开头的行即失败。

    `justfile` 只做**单行委托**，不重复实现逻辑（两份实现必然漂移）：`check-dup`、`check-tauri-free`、
    `check-no-cycle`、`check-single-egress` 分别调对应子命令；`check-secrets` 调 `scripts/check-secrets.sh`；
    `check-all` 依次调 `scripts/check-deps.sh all` 与 `scripts/check-secrets.sh`；
    `test-engine` 展开为 `cargo test -p prism-types -p prism-store -p prism-fs -p prism-parse -p prism-anchor -p prism-llm -p prism-mcp -p prism-engine`
    （**不是** `--workspace`——那会编译 shell，证明不了 D-01）。
    `01-VALIDATION.md` 记录的 `just check-dup` 等命令因此保持有效，同时 `bash scripts/check-deps.sh dup`
    在无 just 的机器上等价可用；两处命令等价关系写进 `justfile` 顶部的一行注释。
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 开发者本机 / CI → 仓库 | 依赖方向与密钥卫生的强制点；此边界失守则后续所有 phase 的架构约束退化为口头约定 |
| 仓库 → 公开分发（未来的公证 DMG） | 提交进仓库的明文密钥会随源码与构建产物一并流出 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-03a | Information Disclosure | 提交进仓库的明文 API key / bearer token | high | mitigate | `scripts/check-secrets.sh` 静态检查进 CI，每次 push 强制执行；反证项要求它在注入假密钥时确实变红 |

| T-01-16 | Elevation of Privilege | engine crate 经普通或 build 依赖间接链接 tauri，绕过 D-01 的可测试性边界 | medium | mitigate | `check-deps.sh tauri-free` 用 `--edges normal,build` 覆盖 build script 路径 |
