<objective>
关闭上轮 WR-08 与上轮 IN-06 —— dev 冒烟通路的输入边界与失败可听见性：

- **上轮 WR-08**：`dev_smoke_stream` 在四行代码里同时违反本文件自己写下的两条纪律。`total: u32` 未校验，`smoke::generate` 每次迭代发一条 IPC 消息，`total = u32::MAX` 是 42.9 亿条；前端固定传 1000，但这个参数对 WebView 里的任何脚本都可达（配合上轮 WR-07 与 CR-02 更是如此）。更结构性的是：`dev_smoke_stream` 是 `async fn` 却直接调 `smoke::generate` 而不经 `delegate` 的 `spawn_blocking`——模块头第 47-51 行解释了为什么这很重要（「一次慢查询会卡住整个 IPC 线程」），而这是本文件唯一不遵守它的命令。`Channel::send` 是同步的，这个循环不会让出。
- **上轮 IN-06**：冒烟页用同一个 `notice` state 承载成功（「样例文档已写入。」）与失败（`errorCopy(err)`，含 listen 被拒的文案），全部渲染在 `role="status"` 里。`status` 是礼貌 live region，辅助技术不会打断。`Settings.tsx` 的 `NoticeLine` 在 error tone 上正确地切到 `role="alert"`，而 `DevSmoke.test.tsx` 用 `findByRole("status")` 把较弱的行为编码进了断言。

Purpose: 上轮 WR-07（01-21 Task 3）把 dev 命令从 release 面上摘掉了，但 debug 形态下这条通路仍然存在，而 dev 冒烟页正是本 phase 四条不可逆决策的人工验证入口——它自己不能是「点了没反应也没有报错」。

Output: 一条有输入上界、不阻塞 IPC executor、且失败会被读屏打断播报的冒烟通路。
</objective>

## Trust Boundaries

| Boundary | Description |

| WebView 内的任意脚本 → `invoke("dev_smoke_stream", { total })` | debug 形态下这条通路存在；`total` 是完全不可信的输入 |

| 冒烟页通知 → 辅助技术 | 失败被渲染进礼貌 live region 等于失败不被播报 |
