关闭本轮 WR-04（≡ 上轮 WR-11）与本轮 IN-04 的第一条：`scripts/check-deps.sh` 的 `check_dup` 用 `|| true` 吞掉 `cargo tree` 的非 0 退出，随后 `grep` 在空串上找不到东西，函数打印 `OK: no duplicate rusqlite/reqwest/libsqlite3-sys` 并返回 0——**断言在它什么都没学到的时候报告成功**。verifier 用一个恒失败的 `cargo` 桩实测复现过。

  <name>Task 1: check_dup 区分「cargo tree 跑不起来」与「跑起来了没有重复」</name>
  <files>scripts/check-deps.sh</files>
  <read_first>
    - `scripts/check-deps.sh` 第 32-43 行 `check_dup`（`|| true` 在第 36 行）
    - `scripts/check-deps.sh` 第 45-186 行其余六条断言 —— 它们都让 `cargo tree` 在 `set -e` 下大声失败，只有 `check_dup` opt out 且注释未给理由
    - `scripts/check-secrets.sh` 第 66-71 行 —— 它把本缺陷（当时记作 WR-11）当作「承重的 `|| true`」的反面教材写进了注释；改完后该段引用仍需成立或同步更新
    - `.planning/phases/01-foundation-skeleton/01-REVIEW.md` WR-04 —— verifier 用 PATH 上的 `cargo` 桩做过端到端复现，命令与输出在那里
  </read_first>
  <action>
    把 `check_dup` 改成先捕获退出码再判断输出：用一个局部 `rc` 变量接住 `cargo tree --workspace --duplicates --edges normal` 的退出码（命令替换失败时不让 `set -e` 直接掐断函数，而是把 rc 记下来）。`rc` 非 0 时打一条含退出码的 FAIL 到 stderr（消息要说明是**命令没跑起来**，与「发现重复」是两件事）并 `return 1`；`rc` 为 0 时才走既有的 `grep -Eq '^(rusqlite|reqwest|libsqlite3-sys) v'` 分支。

    在函数上方的注释里补一句：这里刻意不用 `|| true`——`check-secrets.sh` 的 `scan` 里那个 `|| true` 是承重的（`git grep` 无命中时退出 1，吞掉它才能把「干净」和「失败」分开），而这里被吞掉的恰好是失败本身，两者形态相同性质相反。

    `all` 模式下 `check_dup` 是第一条，`set -e` 会让它的非 0 返回终止整个运行——保持这个行为，不要给它加任何 `|| true` 兜底。
  </action>
  <verify>
    <automated>bash scripts/check-deps.sh dup</automated>
  </verify>
  <acceptance_criteria>
    - `bash scripts/check-deps.sh dup` 退出 0 并打印既有的 `OK: no duplicate rusqlite/reqwest/libsqlite3-sys`
    - **非恒真反证（必须实跑并把输出抄进 SUMMARY）**：在临时目录建一个名为 `cargo` 的可执行桩（内容为打一句话到 stderr 后 `exit 1`），以 `PATH=<stub_dir>:$PATH bash scripts/check-deps.sh dup` 运行 → 退出码为 1，且 stderr 出现新的「命令没跑起来」FAIL 消息（含退出码）。改动前同一实验的实测结果是打 OK 并退出 0
    - 同一桩下 `PATH=<stub_dir>:$PATH bash scripts/check-deps.sh all` 也退出非 0（`all` 的第一条即中止）
    - `bash scripts/check-deps.sh all` 在真实 cargo 下七条全 OK 并退出 0

  <action>
