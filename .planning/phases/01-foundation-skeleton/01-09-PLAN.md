    `src/lib/useEngineInvalidation.ts` 的结构：
    在 `useEffect` 中调 `listen<EngineEvent>('prism://changed', handler)`，handler 按 `payload.kind`
    分流——`resync` 走**无参** `invalidateQueries()` 做全量失效，其余按 `['docs', projectId]` 精确失效。
    effect 的返回值**必须**是清理函数：`listen` 返回的是 `Promise<UnlistenFn>`，所以清理写成
    `() => { p.then(un => un()); }`。**遗漏 cleanup 是这个 pattern 最常见的 bug**——React 19
    StrictMode 下 effect 会执行两次，漏掉清理会注册两个 listener，一条 coarse event 触发 N 次
    refetch，且每次热更新翻倍。依赖数组只放 `queryClient`。

    `src/lib/ipc.ts` 追加对全部命令的类型化封装（每个函数一行 `invoke`），并定义与 Rust 侧
