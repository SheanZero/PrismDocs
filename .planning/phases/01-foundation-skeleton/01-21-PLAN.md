<objective>
关闭本轮 WR-10、本轮 IN-02（≡ 01-VERIFICATION.md 新增的三条无编号 warning 之一）、上轮 WR-07，以及上轮 IN-01：

- **本轮 WR-10**：`DEFAULT_LOG_FILTER = "info"` 与它上方的注释刻意**不**给 `prism_mcp` 开 `debug`，理由是日志 sink 本身是新增外泄面（T-01-58）。第 44 行随即把这个面的控制权无上限地交给一个环境变量：`EnvFilter::try_from_default_env()` 原样接受 `RUST_LOG=trace` 并施加到每个 target。这不是理论问题——`rmcp-2.2.0` 的 streamable http server 里有 `tracing::trace!(?message)`，即完整 MCP 消息转储；Phase 5 起那些消息载有评论正文与文档摘录，正是 `record_receipt` 刻意不记的东西。一个导出的环境变量，或某人 shell profile 里一条遗留的 `RUST_LOG`，就把它装回来。
- **本轮 IN-02**：`tracing_init_installs_a_global_subscriber_and_is_idempotent` 的第一条断言要求**首次** `init_tracing()` 返回 true，而 dispatcher 是进程全局的、cargo 多线程跑测试二进制。它今天成立只因为 `prismdocs-shell` 单测二进制里没有第二处装 subscriber（`commands.rs` / `bus_adapter.rs` / `smoke.rs` 都有 `mod tests`）。一旦有人为了断言日志输出而加一个，这条测试开始非确定性地闪红，且失败消息指向错误的代码。
- **上轮 WR-07**：`generate_handler!` 无条件注册 `dev_ping` / `dev_emit_bus_event` / `dev_smoke_stream` / `dev_seed_sample_docs`。`App.tsx` 摇掉的是 dev **路由按钮**，不是 dev **命令**。其中 `dev_seed_sample_docs` 会往用户真实库里写三份 fixture 文档加一行 `smoke-project`，schema 层面与真实导入不可区分，Phase 2 时还在那里。
- **上轮 IN-01**：`src-tauri/tests/ipc.rs` 里三处注释计数与其下方数组长度不符（写「六个」的是 `[&str; 7]`，写「两个」的是 `[&str; 3]`，写「八个」的是 `[&str; 10]`）。

Purpose: 前三条都指向同一件事——01-13 刚把日志 sink 装起来、把 CSP 装起来，这两件事同时放大了「日志里会出现什么」与「注入后能调到什么」的后果。现在是收口成本最低的时刻。

Output: 一个有上限的日志过滤器、一条不依赖进程全局前置条件的 tracing 测试、一个不含写用户数据命令的 release IPC 面。
</objective>
