<objective>
Stand up the loopback MCP transport and its entire security boundary — the SC-4 deliverable — as a headless crate with an executable proof for every clause of AGENT-03.

Purpose: AGENT-03 says the MCP surface is loopback-only, workspace-scoped, token-gated, Origin-validated, and write-limited to comment receipts. `01-CONTEXT.md` § Specific Ideas is explicit that this "should have corresponding executable verification, not just be declared." Two library defaults make that harder than it looks: rmcp's `allowed_origins` defaults to an EMPTY list which turns Origin validation off entirely, and rmcp has no server-side bearer-token support at all (its `auth` feature is OAuth2 client-side). Both are silent-pass traps. This plan closes them and pins each with a test.

Output: `serve(listener, engine, token, cancellation)` plus a nine-test suite that fails loudly if any security clause regresses. No tools are implemented — the tool surface belongs to Phases 5/6/7 and this plan is strictly the transport and the boundary.
</objective>

  <action>
Implement `serve(listener, engine, token, cancellation_token)` in `serve.rs`. The caller binds the socket and chooses the port — port selection and the "app is resident" lifecycle are shell concerns that land in plan 01-05, and keeping them out of this crate is what lets the whole suite run headless.

Build the router as: `nest_service("/mcp", StreamableHttpService)` with a `.layer()` carrying the bearer-token middleware. Layer ordering is load-bearing — `.layer()` applies OUTSIDE `nest_service`, so an unauthenticated request is rejected before rmcp sees it, which is exactly what makes a 401 and a 403 independently assertable. Leave a commented anchor on the router for the Phase 6 clip WebSocket route (D-08: one loopback listener serves both needs, different routes) without implementing any clip protocol.

Configure `StreamableHttpServerConfig` explicitly rather than taking the default: attach the caller's child cancellation token, restate `allowed_hosts` as localhost / 127.0.0.1 / ::1 so the intent is greppable, and — critically — set `allowed_origins` to a NON-EMPTY list containing the app's own loopback origins at the bound port. The default is an empty vector, and the library skips Origin validation entirely when it is empty, which would make the Origin clause of SC-4 pass without testing anything. Note in a code comment that a MISSING Origin header is required to pass: Claude Code and Cursor are not browsers and send none, so rejecting a missing Origin would break the primary integration. Origin validation exists to stop browser-originated cross-site calls; the token layer is what stops unauthenticated callers.

Implement the token middleware in `auth.rs`: read the `Authorization` header, require the `Bearer ` prefix, and compare the remainder against the expected token with `subtle::ConstantTimeEq` over raw bytes. Never use `==` on strings — it short-circuits on the first mismatched byte and is a timing oracle for a loopback secret. Reject an absent header, a malformed header, and an empty bearer value identically with 401, and never echo the presented token into the response body or a log line.

Implement `token.rs`: `generate_install_token` draws 32 bytes from `rand::rngs::OsRng` and encodes them base64url. Do not use a v4 UUID as a security token — 122 bits from a PRNG whose CSPRNG properties are implementation-defined is not the same guarantee.

Implement `PrismMcpServer` in `handler.rs` as an rmcp `ServerHandler` constructed with the workspace identifier baked in, exposing server info and ZERO tools. There must be no tool parameter anywhere that selects a workspace — that is how a malicious client would enumerate other projects. `ProtocolVersion::LATEST` in rmcp 2.2 already resolves to the 2025-11-25 revision the project pins, so accept the default rather than hard-coding a version string, and record in the SUMMARY that the pin is satisfied by construction.

Make the handler generic over the read trait plus the one-method agent write trait from `prism-core`. Do not import the app-only write trait; widening that bound later is the review signal this design exists to produce.

Wire `tracing` so the library's own rejection warnings are emitted — rmcp already warns on a rejected Host or Origin, which is free security-logging evidence. Log rejections; never log the token or any request body.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client → loopback HTTP endpoint | Any local process, and any browser page on the machine, can reach 127.0.0.1 |
| browser page → loopback endpoint | A malicious web page can issue cross-origin requests to a local server (the DNS-rebinding class) |
| MCP handler → Engine facade | The agent's entire authority over user data crosses here |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-01 | Spoofing / Elevation | DNS rebinding against the local MCP server | high | mitigate | Loopback-only bind plus rmcp's `allowed_hosts` and an EXPLICITLY non-empty `allowed_origins`, returning 403. Enforced by `bind_is_loopback_only`, `rejects_foreign_origin`, `rejects_foreign_host`, with `accepts_missing_origin` guarding the real-client path. |
| T-1-02 | Spoofing | Request with no credential | high | mitigate | Bearer-token middleware layered outside the mounted service, so an unauthenticated request never reaches session handling. Enforced by `rejects_missing_token` and `rejects_empty_token`. |
| T-1-03 | Spoofing | Token guessing / timing oracle | high | mitigate | 32 bytes from the OS CSPRNG, base64url-encoded, compared with `subtle::ConstantTimeEq` over raw bytes — never string equality. Enforced by `rejects_wrong_token`. |
| T-1-04 | Elevation of Privilege | Agent write-surface escape | high | mitigate | The MCP crate is generic over the read trait plus a one-method agent write trait and names the app-only write trait nowhere. Enforced by `agent_write_surface_is_minimal` and `agent_write_trait_has_one_method`. |
| T-1-05 | Information disclosure | Malicious client enumerating other workspaces | medium | mitigate | The handler is constructed with its workspace identifier baked in and exposes no workspace-selecting parameter. Enforced by `handler_is_workspace_pinned`. |
| T-1-17 | Repudiation | Rejections not observable | low | mitigate | `tracing` subscriber wired so the library's own Host/Origin rejection warnings are captured; rejections are logged, secrets never are. |
</threat_model>
