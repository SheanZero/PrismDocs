<objective>
Make "your data is yours, it lives in one directory, and it survives you moving the folder" true — the local-first half of SC-2.

Purpose: WAL is the reason D-14 exists and also the reason NFR-02's backup story is subtle. In WAL mode a database is three files (`.db`, `.db-wal`, `.db-shm`), so the obvious implementation of D-12 — copy `prism.db` — silently loses every committed-but-uncheckpointed transaction. And D-13's move/rename survival is unimplementable if identity is the path. This plan settles both, plus the durability assertions NFR-02 is graded on.

Output: a store crate that can open, migrate, scope, back up, and re-associate a project entirely headless — no Tauri, no webview, no network. The shell wires it to buttons in plan 01-05.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-chosen workspace path → store | An arbitrary directory path, possibly containing symlinks, becomes a filesystem root |
| project marker file → identity resolution | A file inside the user's repository determines which data directory is opened |
| MCP reader ↔ app writer | Two independent pooled connections on one database file |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-05 | Information disclosure | Cross-workspace read | medium | mitigate | Every project-scoped query takes a workspace identifier as a bound parameter; the server instance is constructed with its workspace baked in and exposes no parameter that selects another. Enforced by `workspace_scoping`. |
| T-1-10 | Tampering | SQL construction | medium | mitigate | rusqlite named/positional parameters exclusively; no query is assembled with string formatting anywhere in `prism-store`. |
| T-1-11 | Tampering | Crafted workspace path or symlinked marker directory | medium | mitigate | `std::fs::canonicalize` the workspace root, then verify every derived path still begins with it. Enforced by `path_outside_workspace_root_is_rejected`. |
| T-1-16 | Denial of service (data loss) | Naive WAL backup | high | mitigate | `VACUUM INTO` rather than a file copy; temp-then-rename so an interruption leaves no partial artifact. Enforced by `backup_captures_uncheckpointed_writes` and `interrupted_backup_leaves_source_intact`. |
</threat_model>
