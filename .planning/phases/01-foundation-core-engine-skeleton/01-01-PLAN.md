## Phase Goal

Stand up the cross-cutting engine skeleton every later phase depends on — shell-agnostic core, local-first store, secure LLM + MCP boundaries — and resolve the one load-bearing architecture decision so it never gates F1.

> **Planner note (MVP_MODE):** the ROADMAP `**Goal:**` line for Phase 1 is not in `As a / I want to / so that` form. Per the MVP-mode contract a user story is NOT invented here; the goal is carried verbatim. Run `/gsd mvp-phase 1` if the user-story framing is wanted. The user-visible capability this phase proves end-to-end is recorded in `SKELETON.md` § Capability Proven End-to-End.

<objective>
Clear the Wave-0 gate that every other plan in this phase stands on: prove the machine can actually build this stack, lay the Cargo workspace whose crate boundaries the compiler will enforce for the rest of the project, and correct the six build-breaking version pins in the project stack doc before a single line of product code is written.

Purpose: `01-RESEARCH.md` found two pins in `.claude/CLAUDE.md` that make the tree **unbuildable** (`rusqlite_migration` 2.6 requires `rusqlite ^0.40`; `libsqlite3-sys` declares `links = "sqlite3"` so a version split is a hard Cargo error), and it never probed whether Rust ≥ 1.95 or a C compiler exist on this machine. Both are blocking. Discovering either after three plans of work is the expensive failure this plan exists to prevent.

Output: a compiling, testing, lint-clean Cargo workspace + Tauri/React scaffold, a pinned toolchain, and a corrected stack doc.
</objective>
