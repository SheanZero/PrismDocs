<objective>
Give the engine a shell: the loopback MCP server becomes resident with the app on a known port with a stable per-install token, and the store's project-identity and backup capabilities become things a user can actually do.

Purpose: plans 01-03 and 01-04 deliberately built headless crates — the store never resolves its own directory and the MCP crate never binds its own socket, which is what let both be tested without a running app. Those two seams have to be joined somewhere, and that somewhere is the shell. This plan is also the precondition for onboarding step 4: `.mcp.json` cannot be written until a real port and a real token exist.

Output: an app that, once launched, is already an MCP server, and a home screen where the local-first promises of SC-2 are visible rather than merely true in a test.
</objective>

  <action>
Write `src-tauri/tests/mcp_host.rs` first and watch it fail.

Implement `McpHost` in `mcp_host.rs`. Port selection: try the fixed default `DEFAULT_MCP_PORT = 47917` first and scan upward until a bind succeeds, capping the scan at a bounded number of attempts and surfacing a clear error rather than looping. 47917 sits in the 47900–47999 block, which carries no IANA service registration and no common dev-tool default; PA-2 records why 47808–47823, 47001, 47100, and the 3000/5173/8000/8080/9000 cluster were each avoided. Bind explicitly to `127.0.0.1` — never `0.0.0.0`, and never a hostname that could resolve elsewhere.

Token lifecycle: read the per-install token from the keychain at account `mcp.install_token` under service `PrismDocs`. If it is absent, mint one with the core's CSPRNG generator and store it; if it is present, REUSE it. Minting a fresh token on every launch would silently invalidate every `.mcp.json` the user has already generated, which is the same failure as changing the port. Exactly one keychain entry, ever.

Startup: in `lib.rs` `setup()`, resolve the app-support base directory with `dirs::data_dir()` joined to `PrismDocs` — not Tauri's `app_data_dir()`, which resolves to the reverse-DNS bundle identifier (PA-1) — build the `Engine`, then spawn the MCP host on a Tokio task so the server is live the moment the window is (D-09). Hold the `CancellationToken` in Tauri state.

Shutdown: on app exit, cancel the token and await the drain so in-flight requests finish rather than being truncated mid-response, then release the port.

Expose `get_mcp_status` in `commands/mcp.rs` returning the bound port and the running state — but NOT the token. The token reaches the client config through the indirection chosen in plan 01-06, never through an IPC response that could end up in a devtools log.

Add `McpStatusChip.tsx` showing the bound port and a live running indicator, and regenerate the committed bindings.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local network → bound socket | The address the listener binds determines who can reach the MCP endpoint |
| process → macOS Keychain | The per-install token crosses into and out of OS-managed storage |
| webview → IPC responses | Anything returned to the renderer is visible in devtools |
| user-chosen directory → project resolution | An arbitrary path from a native picker becomes a filesystem root |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-01 | Spoofing / Elevation | Socket bind address | high | mitigate | Bind a `127.0.0.1` literal; no wildcard and no hostname bind exists in the shell crate. The core's `bind_is_loopback_only` test covers the serving side; this task covers the binding side. |
| T-1-03 | Spoofing | Token lifecycle across restarts | high | mitigate | Mint-once-then-reuse from the keychain, exactly one entry. A per-launch re-mint would push users toward pasting the token somewhere convenient and insecure. Enforced by `token_is_minted_once_and_reused`. |
| T-1-07 | Information disclosure | Token reaching the renderer or a log | high | mitigate | `get_mcp_status` returns the port and state only; the token is not in its response type and is never printed. Enforced by `token_is_never_persisted_outside_the_keychain`. |
| T-1-11 | Tampering | Arbitrary directory chosen by the user | medium | mitigate | The shell passes the raw path to the facade, which canonicalizes it and confines every derived path beneath it (plan 01-03, `path_outside_workspace_root_is_rejected`). The shell adds no unchecked path handling of its own. |
</threat_model>
